# 客户与授信关联

`public.client(id, name, fullname, type, subtype)` 保存共享客户身份，`name` 是唯一业务简称。全名允许为空；汇总客户、自然人和来源只有简称的机构不补造法律全名。一级分类为银行、理财子、券商、基金、营业部客户、其它；银行性质和券商自营/资管放在 `subtype`。银行资管统一另建“银行简称+资管”客户，`type=理财子`、`subtype=银行资管`，不复用母行法律全名；未明确标注资管的银行客户归银行自营。

## 关联规则

- `financing.debt.client_id` 每笔最多关联一个客户，各继承子表分别安装外键、索引和触发器。原 `counterparty` 留作业务原文，不覆盖。经人工确认的 2021-09-06 集团借款（5亿元、2021-09-14到期）已将错误的本公司交易对手改为集团公司，导入转换执行同一精确纠正规则以防旧工作簿重复建账。初始回填只更新空关联，手工指定的客户优先；修改交易对手时重新识别，其他字段修改不改变人工关联。
- `public.client_alias(alias, client_id)` 仅保留精确特殊映射，不存正则、`match_kind` 或 `notes`。`alias` 是 `public.client_match_key` 生成的标准化键；实际投资人例外优先于通用规则。
- 通用规则按 `client.name/fullname` 识别，统一全半角、空白、引号、来源前缀、公司后缀及“农村商业银行/农商银行→农商行”。银行名称允许唯一且省份不冲突的省份简称与“银行/行”变体；同名跨省或多个候选保持空关联。吸收合并备注不改变原客户身份。
- 明确的“资管/资管部/资产管理/资产管理部”后缀（含括号）归独立资管客户；金市/自营及无标识归银行。资管客户尚未维护时保持空关联并提示维护，不能回退到银行主体。
- 具名资管/信托/私募产品只匹配已建档的完整产品名，并要求前文为公司账户及可选的“代/代表”。理财产品按已知理财子的名称前缀识别；同时出现两个理财子名称时，需精确例外才能认定归属。管理人公司名称中的“资产管理”不构成银行资管标记，未知产品不能猜测投资人。
- 当前特殊映射包括招行三条实际投资人记录、信银管理但归属中银理财的产品及少量名称错字/非标准简称。删减别名时在同一事务校验全部负债名称、授信名称、客户简称/全名和旧精确别名的识别结果，任何归属变化均回滚。
- `credit.institution_client` 是唯一的静态一对多关联表，不保存报告日，也不再另存 `client_mapping`。每个客户只归属于一个授信主体，通过唯一客户约束防止重复计入；不再保存收益凭证、同业拆借两个品种开关。上海农商行（金市）关联上海农商行，上海农商行（资管）关联上海农商行资管，其它银行同理。
- 新增授信优先采用已有静态关联；没有关联时，仅当完整名称或 `&` 合并名称全部精确识别且不与既有归属冲突才自动关联。重导、删除或补导任意报表日均保留静态关联，修改关联统一影响所有日期的融资额度归属。省联社成员按人工确认清单逐一维护，运行时不按省份字符串自动扩大范围。

## 金额和历史

`financing.credit_usage_as_of(date)` 在融资领域读取已生效、报告日尚未到期/结清/关闭的收益凭证和同业拆借本金（元）。`credit.item_usage` 按关联主体求和并除以一亿元，替换两个品种的展示使用额；未关联保持 NULL。

`credit.institution_usage` 总已用始终为 `item_usage` 有效分项之和；收益凭证与拆借取融资余额，其余分项取授信维护值。`institution.total_used` 由数据库触发器维护为原始 `item.used_amount` 之和，增删改分项及直接修改总额均不能留下独立差额。`usage_reconciliation` 继续展示原始融资分项与融资台账的差额。导入先检查工作簿总已用与分项合计，差异超过 0.000001 亿元时明确警告机构、原数、合计和差额，并按合计导入；入库后补充融资差异与缺失关联警告。

银行与理财子分别建客户，即使授信合并也不把客户法人合并。营业部客户和具名投资产品可以有客户关联但没有银行授信，这是正常的业务范围差异。原始负债无交易对手时不创建虚拟投资人补齐关联。

## 初始化与管理员维护

先运行融资 migration（含公共客户主表及负债外键），再运行授信 migration；不要在生产执行临时 DDL。

```sh
pnpm financing:db:init -- --schema-only
pnpm credit:db:migrate
node scripts/maintain-clients.mjs /absolute/path/client-manifest.json
node scripts/maintain-clients.mjs /absolute/path/client-manifest.json --apply
node scripts/reconcile-client-usage.mjs /absolute/path/reconciliation.json
```

清单字段：`clients` 为上述主表字段（不传 id）；`aliases` 为 `alias/clientName`；`creditMappings` 为 `institutionName/clientName/notes`。首次运行默认为事务回滚预览，`--apply` 才保存；来源清单与真实台账核对结果放在未跟踪的运行目录，不提交业务快照。

维护清单按名称更新客户和给定别名/静态归属，不删除未提及客户、旧别名或关联。给定别名若已能由通用规则识别，不重复写入；将旧例外显式改回通用规则的归属时，删除该条例外。旧清单的 `matchKind` / `notes` 别名字段会被拒绝，防止再次灌入旧规则。改变归属需显式维护 `institution_client`；同一客户重复关联多个授信主体会被数据库拒绝。全部融资品种统一按客户身份汇总，银行与资管不能互相代入。负债详情可编辑客户 ID；修改历史金额、日期、现金流后按需要显式刷新既有月度衍生指标。

当前 Auth0 模式经 `/financing/data/api` 由 Worker 编译白名单 SQL、通过 Hyperdrive 访问融资 schema，并在事务内使用 `authenticated` 角色与 RLS；生产未开通 Neon 托管 Data API，因此无需刷新托管 schema cache。若将来重新启用托管 Data API，DDL 后须刷新缓存。公共客户表和授信内部视图不向数据后台开放，继续沿用融资写权限和审计。
